# AWS 클라우드 인프라 트러블슈팅 보고서

## 1. 문제 개요

| 항목 | 내용 |
|---|---|
| 프로젝트 | Codyssey AWS Cloud Deployment |
| 발생 단계 | 4단계. EC2 인스턴스 생성 및 설정 |
| AWS 리전 | ap-northeast-2 (Seoul) |
| 관련 리소스 | EC2, EBS |
| 문제 유형 | EC2 종료 상태 및 리소스 정리 확인 |

EC2 인스턴스를 생성한 후 Advanced details 설정을 변경하기 위해 기존 인스턴스를 종료하고 새로운 인스턴스를 생성했습니다. 그러나 기존 인스턴스가 종료된 이후에도 EC2 목록에 계속 표시되어 정상적으로 삭제되었는지 확인이 필요했습니다.

## 2. 증상

AWS EC2 콘솔에서 기존 인스턴스를 종료했지만 인스턴스 목록에는 총 2개의 인스턴스가 표시되었습니다.

- 기존 인스턴스: Terminated
- 새로 생성한 인스턴스: Running
- 신규 인스턴스 상태 검사: 3/3 checks passed

기존 인스턴스가 목록에 남아 있어 삭제가 완료되지 않았거나, 불필요한 리소스로 인해 추가 비용이 발생할 가능성이 있는지 확인해야 했습니다.

## 3. 원인 가설

**가설 1. EC2 종료 작업이 정상적으로 완료되지 않았을 가능성**

인스턴스 종료 요청 이후 AWS 내부에서 종료 처리가 진행 중이기 때문에 목록에 남아 있을 수 있다고 판단했습니다.

**가설 2. 종료된 EC2의 기록이 일시적으로 유지되는 상황**

EC2 인스턴스가 Terminated 상태로 전환되더라도 AWS 콘솔에서는 종료된 인스턴스의 기록이 일정 시간 표시될 수 있다고 가정했습니다.

**가설 3. 기존 인스턴스의 EBS 볼륨이 남아 있을 가능성**

EC2 인스턴스가 종료되었더라도 연결된 EBS 볼륨이 남아 있다면 별도의 스토리지 비용이 발생할 수 있으므로 확인이 필요하다고 판단했습니다.

## 4. 검증 과정

### 4-1. EC2 인스턴스 상태 확인

AWS 콘솔에서 다음 경로로 이동했습니다.

EC2 → Instances → 인스턴스 목록

기존 인스턴스와 신규 인스턴스의 상태를 비교했습니다.

| 구분 | 확인 결과 |
|---|---|
| 기존 EC2 | Terminated |
| 신규 EC2 | Running |
| 신규 EC2 상태 검사 | 3/3 checks passed |
| 인스턴스 유형 | t3.micro |

기존 인스턴스의 상태가 Terminated로 표시되어 종료 요청이 처리되었다는 사실을 확인했습니다.

### 4-2. AWS 인스턴스 종료 동작 확인

AWS에서는 종료된 EC2 인스턴스가 콘솔 목록에 일정 시간 남아 있을 수 있다는 점을 확인했습니다.

따라서 목록에 인스턴스가 표시되는 것과 실제 인스턴스가 실행되고 있는 것은 구분해야 한다고 판단했습니다.

### 4-3. EBS 볼륨 확인

추가 과금을 방지하기 위해 다음 항목을 점검 대상으로 정했습니다.

- EBS 볼륨 개수
- Volume state
- 현재 EC2 인스턴스와의 연결 여부
- 종료된 EC2의 잔여 볼륨 존재 여부

AWS 콘솔 확인 경로:

EC2 → Elastic Block Store → Volumes

EBS 볼륨에 대해서는 개수뿐 아니라 실제 연결 상태를 함께 확인해야 합니다.

## 5. 조치 내용

**첫째, EC2 인스턴스의 상태를 기준으로 종료 여부를 판단했습니다.**

기존 인스턴스가 Terminated 상태임을 확인하고, 콘솔 목록에 남아 있다는 이유만으로 추가 삭제 작업을 반복하지 않았습니다.

**둘째, 정상 운영 중인 인스턴스를 구분했습니다.**

새로 생성한 인스턴스가 Running 상태이고 3/3 상태 검사를 통과한 사실을 확인했습니다.

**셋째, EBS 잔여 리소스 점검 절차를 정리했습니다.**

기존 인스턴스의 볼륨이 남아 있을 가능성을 고려하여 EBS 목록에서 볼륨 개수와 연결 상태를 확인하도록 점검 항목을 정리했습니다.

## 6. 결과

기존 EC2 인스턴스는 Terminated 상태였으며, 새로 생성한 EC2 인스턴스는 Running 및 3/3 checks passed 상태임을 확인했습니다.

이를 통해 종료된 인스턴스가 콘솔 목록에 표시되는 현상만으로 종료 실패를 판단해서는 안 된다는 점을 확인했습니다.

다만 최종적인 리소스 정리 여부를 판단하려면 EBS 볼륨의 연결 상태와 잔여 리소스 확인 결과까지 함께 기록해야 합니다.

## 7. 재발 방지

동일한 상황에서 불필요한 리소스가 남지 않도록 다음과 같은 점검 절차를 적용하겠습니다.

1. EC2 생성 전 AMI, 인스턴스 유형, 네트워크, EBS, Advanced details를 모두 확인합니다.
2. 인스턴스 종료 시 Instance state가 Terminated인지 확인합니다.
3. 종료 후 EBS 볼륨이 남아 있는지 확인합니다.
4. 새 인스턴스 생성 시 기존 리소스와 구분할 수 있도록 이름과 인스턴스 ID를 확인합니다.
5. 실습 종료 시 리소스 정리 체크리스트를 활용해 잔여 리소스와 과금 가능성을 점검합니다.
